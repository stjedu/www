BEFORE YOU START

先準備好，再一起上線

老師需要準備

一台可上網的電腦、Chrome 或 Edge、可收信的電子郵件，以及自己的 GitHub 帳號。第一次使用者先完成註冊與信箱驗證。

這堂課的完成標準

能以自己的網址開啟首頁、看見自己的教學介紹，並修改一次內容。請同事用另一台裝置開啟，確認分享成功。

本次採用「公開靜態網站」練習。範本使用虛構教學內容；公開上傳前，請先移除學生名冊、成績、密碼與金鑰。

先認識三個詞：GitHub 是放檔案的平台；Repository（倉庫） 像專案資料夾；GitHub Pages 將靜態網頁轉成可瀏覽的網站。

01

確認帳號，規劃你的網址

先分清楚 GitHub 使用者名稱與個人顯示名稱。

  1. 開啟 GitHub。已有帳號選 Sign in；尚未註冊選 Sign up，依畫面完成註冊與驗證。
  2. 從帳號選單進入個人資料，確認網址 github.com/你的帳號 中的使用者名稱。它不是中文姓名，也不是電子郵件。
  3. 在下方填入帳號，查看應使用的倉庫名稱與網址。這只是規劃工具，不會建立或登入任何帳號。
範例帳號：teacher-demo；請改成你實際擁有的帳號。

02

建立放網頁檔案的倉庫

Repository 就是這個網站的檔案存放處。

  1. 點選 GitHub 右上角 ＋ → New repository，或開啟 建立倉庫頁面。
  2. Owner 選自己的帳號；Repository name 填入上一步產生的倉庫名稱。
  3. 本堂課使用免費帳號的公開倉庫：選 Public。啟用 Add README，讓倉庫有初始內容。
  4. 確認名稱後按 Create repository。如果同名倉庫已存在，先確認是否為自己的既有網站，再決定沿用；不要覆蓋不確定用途的檔案。

03

準備你的第一份首頁

先完成一個小網站，再慢慢增加內容。

  1. 下載下方「教師首頁範本」，存到自己的資料夾。下載後檔名會是 index.html。
  2. 連按兩下，用瀏覽器預覽。看到「我的教學小站」，表示 HTML 可以正常開啟。
  3. 如果要改文字，可用記事本或慣用編輯器開啟。先改「我是＿＿老師」與科目名稱，再以 UTF-8 儲存。保留 .html 副檔名。

檔名必須是小寫 index.html，避免變成 index.html.txt。本範本不需要額外圖片、CSS 檔或安裝套件。

請建立適合 GitHub Pages 的繁體中文教師個人網站，輸出一份完整 index.html。包含教師介紹、課程教材、學習任務三區，採深藍與暖橘配色，支援手機與鍵盤操作。將 CSS 直接寫在 HTML 中，不使用建置工具、登入或後端服務。未知資料使用「待填寫」，不要虛構經歷與學生資料。請附檔案儲存與上傳說明。

04

上傳檔案，儲存第一次版本

Commit changes 代表確認保存這次檔案變更。

  1. 回到剛建立的倉庫，在 Code 頁面選 Add file → Upload files。
  2. 將 index.html 拖入上傳區。如果有自己的 CSS 或圖片，也一起上傳並保留資料夾結構。
  3. 在變更說明填入「建立我的教學首頁」，再按 Commit changes；若有分支選項，選直接提交至本堂課使用的 main。
  4. 確認檔案清單中，index.html 與 README.md 在同一層。

如果拿到 ZIP，先解壓縮，再上傳裡面的網頁檔案。只把 ZIP 放進倉庫，不會自動變成網頁。
05

啟用 GitHub Pages

這一步把「放檔案的倉庫」連接成「可瀏覽的網站」。

  1. 在這個倉庫中選 Settings，再由側欄選 Pages。不是個人帳號的 Settings。
  2. 在 Build and deployment 中，將 Source 設為 Deploy from a branch。
  3. Branch 選 main，資料夾選 / (root)，按 Save。若你的初始分支名稱不同，請選實際放有 index.html 的分支。
  4. 等待部署完成，再查看 Pages 頁面的 Visit site。更新可能需要最多約 10 分鐘，可在倉庫 Actions 頁籤查看部署結果。

06

驗收成果，練習更新一次

不只「有網址」，也要確認別人真的看得到。

  1. 點選 Visit site，確認網址使用 github.io，畫面顯示你的教學首頁，而非倉庫檔案清單。
  2. 把網址交給旁邊老師或用手機開啟，確認標題、文字與版面正常。
  3. 回到倉庫，點選 index.html，使用編輯功能將一行文字改成自己的教學理念，再保存 Commit changes。
  4. 等待再次部署完成後重新整理網站。能看見新文字，即完成「建立 → 發布 → 更新」循環。
課堂成果分享：請交「網站網址＋一張首頁截圖」，不需要提供密碼、驗證碼、Token 或完整帳號設定畫面。
WHEN YOU GET STUCK

老師最容易卡住的地方

網址出現 404，怎麼檢查？

先確認部署已完成；再比對倉庫名稱、Pages 發布分支與資料夾、首頁檔名與位置。個人首頁和專案網站的網址不同，優先使用 Pages 設定頁提供的 Visit site。

只看到 README，沒有我的首頁？

檢查 index.html 是否真的上傳到發布來源資料夾、是否多放了一層資料夾，以及檔名是否被加上 .txt。

圖片或樣式消失？

確認相關檔案也已上傳，大小寫與路徑完全相同。建議以相對路徑引用，例如 images/photo.png、style.css；不要使用電腦上的 C:\Users\… 路徑。

內容改了，網頁還是舊的？

先看 Actions 是否部署成功，再等待更新與重新整理；必要時用另一個瀏覽器確認。不要連續改 Pages 設定來催促部署。

老師一定要申請 Token 或安裝 Git 嗎？

本堂課以 GitHub 網站上傳與編輯檔案，不需要 Token、Git 或命令列。熟悉基本流程後，再選擇 GitHub Desktop 或 AI 工具協作。

可以放 Python、登入或學生個資嗎？

Pages 適合 HTML、CSS、JavaScript 靜態網站，不會直接執行伺服器端 Python。請勿將學生個資、成績或金鑰放進公開教材；需要登入或資料庫時應另行規劃適合的服務。

FACILITATOR NOTES

給帶課老師的 60 分鐘節奏

以下為建議安排；註冊、驗證或校園網路可能需要額外時間，最好課前先完成帳號準備。

10′概念與網址規劃
15′建立倉庫、準備範本
20′上傳與 Pages 設定
15′驗收、更新與分享
  1. 示範一小步，再讓老師操作。每段完成一個勾選檢查點，避免一次講完整串操作。
  2. 全班使用同一個範本起步。先改姓名與科目，讓每個人都能辨認自己的成果。
  3. 兩人互相驗收。交換網址，用不同裝置或瀏覽器開啟，找出網址與檔名錯誤。
  4. 進階任務再分流。加一個教材連結、替換主色、建立第二頁；已有個人首頁者可改做 www 專案網站。

課後可延伸的 AI 協作

老師先決定教學目的與可公開內容，AI 協助製作 HTML、調整手機排版與檢查連結；最後由老師預覽、確認並發布。
